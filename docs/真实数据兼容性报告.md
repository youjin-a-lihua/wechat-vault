## 三、`.dat` 附件解码 —— 决定性实测

### 3.1 抽样结果

| 观测项 | D 盘（157 样本） | G 盘（69 样本） |
|---|---|---|
| 文件头 `07 08` 占比 | **100%** | **100%** |
| 单字节 XOR 嗅探命中率 | **100%** | **100%** |
| 嗅探返回的密钥 | **恒为 `0x45`** | **恒为 `0x45`** |
| 嗅探返回的扩展名 | 恒为 `.bmp` | 恒为 `.bmp` |
| **强校验（完整 BMP 结构）通过** | **0 / 157 = 0%** | **0 / 69 = 0%** |
| 失败主因 | `BITMAPFILEHEADER.fsize` 不匹配 | 同左 |

### 3.2 为什么 100% 假阳性？

微信 `.dat` 以**常量** magic `07 08` 开头，BMP 以 `BM`(42 4d) 开头：

```
key = 0x07 ^ 0x42 = 0x45      ← 对每个文件都一样
```

嗅探算法测到的是「文件以 `07 08` 开头」这个**常量事实**，
不是真实密钥。XOR 之后首 2 字节确实变成 `BM`，但：

```
解出后: 42 4d 13 77 4d 42 45 41 45 45 e1 b9 45 45 44 fa ...
        B  M  ?? ?? M  B  E  A  E  E  ?? ?? E  E  D  ?? ...
        └─ 只有前 2 字节对，后面全是垃圾
BMP头: fsize=1112373011 off=1162197473 hdrsize=1478687300
       dim=829603766x-1179970429 planes=21283 bpp=35374
       └─ 全部非法 → 不是图片
```

### 3.3 排除的其他可能

| 假设 | 验证 | 结果 |
|---|---|---|
| 单字节 XOR | 256 密钥穷举 + 强校验 | ❌ 0 个合法 |
| 多字节重复 XOR | 自相关检测周期 | ❌ 无稳定周期 |
| 跳过头部再 XOR | 试 0/1/2/4/6/8 字节偏移 | ❌ 0 个合法 |
| 尾部周期 = 19 字节 | 手工定位 | ⚠️ 仅尾部 padding 重复，非全局密钥 |

**判定：微信 4.x `.dat` 为会话级真加密，密钥不在文件内，离线不可解。**

## 五、附件怎么才能真正拿到？

### 路线 A（推荐 · 合规零风险）

```
微信 → 设置 → 聊天记录管理 → 导入与导出 → 导出到电脑
```

产出**明文**记录 + 附件，直接被本项目的可读轨消费。

### 路线 B（进阶 · 需运行时）

趁 `Weixin.exe` 运行，从进程内存提取 V2 会话密钥：

```bash
python archiver/wv_dat.py decode --src ./msg --dst ./media \
    --aes-key <32位hex>
```

## 六、本轮修复的 4 个真 Bug

| # | 症状 | 根因 | 修复 |
|---|---|---|---|
| 1 | 解码整批崩溃 `IndexError` | 假 V1 magic（`07 08` 随机命中）跳进 AES，`_expand_key` 越界 | 加 `_looks_like_aes_v1v2` 严格判据 + 边界保护 |
| 2 | 统计里出现「会话 `01`」「会话 `{(1)」 | 归档器对所有 `.txt/.json/.html` 一网打尽 | 新增 `looks_like_chat_export` 自证机制 |
| 3 | 推广文被误判为聊天记录 | 时间戳正则 `20\d{2}[-/年]\d{1,2}` 吞掉「2026年度」的数字 | 正则加分隔符与数字边界约束 |
| 4 | `.dat` 报"成功"但产出的是垃圾 | 只看 magic（弱校验） | 改用 `strong_validate`（完整结构），如实报告 |

另有 2 个顺带发现：

- **`V1_KEY_HEX` 只有 8 字节**（`cfcd208495d565ef`），送进 AES-128 必崩 ——
  已修正为完整 `md5("0")` 的 32 位 hex（16 字节）。
- **元数据 `.dat`**（`alt_name.dat`/`phoneid.dat` 等）被送进图片解码器 ——
  已新增 `is_metadata_dat` 自动跳过。
